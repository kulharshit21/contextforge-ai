## Release notes — ready to paste into GitHub Releases after gates pass

### ContextForge v0.1.0-beta.2 — Security and Reliability Update

ContextForge is a local-first project memory tool for AI coding agents. It preserves verified project decisions, debugging history, test outcomes, blockers, and next steps across coding sessions. This beta focuses on **protecting local project data** and **making recall more reliable**.

### Security: local dashboard filesystem boundaries

- Reject unknown or traversal-style memory file keys before any filesystem write, both at the HTTP route and the memory engine.
- Restrict repository scans to canonical in-workspace directories by default. Reject symlinked targets, escaped parent links and unsafe Windows junction traversal.
- Prevent the scanner from reading external files through symlinked README/package.json/ignore files and external Git metadata pointers.
- External scan opt-in is available only through `CONTEXTFORGE_ALLOW_EXTERNAL_SCAN=1`. **Do not enable this on shared or publicly accessible hosts**: the local dashboard has no multi-user authentication and the opt-in permits filesystem scanning by anyone who reaches it.

### Reliability: saved context survives failures

- Journal repair now uses the shared writer lock, preventing concurrent appends from being silently lost during repair.
- Chat-ingested memories are written to the append-only journal, so they appear in task-scoped recall instead of existing only in the capped Markdown mirror.
- Concurrent Markdown writes refuse lock contention instead of silently overwriting another writer's changes.
- Hand-edited YAML timestamps no longer make memory files unreadable; journal sync correctly deduplicates and counts created records.

### Portable Agent Skill and Python interoperability

- Enforce strict recall character budgets, including long task headings.
- Use UTF-8 for Python CLI pipes on Windows to avoid crashes and corrupted non-ASCII notes.
- Align secret pattern checks and repair backup naming with the Node implementation.
- Fix benchmark harness serialization so Node can read synthetic test journals and failed subprocesses are reported instead of silently scored as zero.

### Dashboard privacy and API safety

- Validate all remaining dashboard API payloads, including request size limits and boolean flags.
- Enforce each project's `local` privacy preference when choosing the AI provider, rather than silently relying only on a global cloud setting.
- Stop returning unused, formerly plaintext `geminiApiKey` and `ollamaUrl` fields in project settings.
- Gracefully skip corrupted saved capsule files rather than breaking the entire project view.

### Installation (beta / source first)

The portable, offline Python Agent Skill can be used independently of the Next.js dashboard. Experimental third-party installer route (Node.js 22.20+, Python 3.10+ required):

~~~bash
npx skills add kulharshit21/contextforge-ai --skill contextforge-memory -a codex
~~~

Alternatively, clone the source and run `npm ci`, `npm link` to use the Node CLI in other local projects.

**No npm registry package is published. Do not use `npx contextforge`.** Agent-specific automatic Skill discovery must be verified in the destination host; copying files does not guarantee activation.

### Verification and known limitations

- CI passed on the source candidate, including Node typecheck/lint/integration/build and Python Skill tests on Ubuntu, Windows, and macOS.
- The `v0.1.0-beta.1` tag remains unchanged; the source of beta.2 should be tagged at an independently verified patched commit.
- The public hosted demo's deployed commit must be checked separately; a successful GitHub merge does not by itself prove Vercel deployed the fix.
- Existing user-local `workspaces/projects.json` files **may still contain obsolete API keys** written by earlier versions. See issue #56. Remove old keys carefully after making a backup, and rotate previously exposed credentials.
- The project does not automatically intercept AI chat history, model compaction, or silent tool usage. Agent memory needs explicit checkpoint/recall.
- Internal benchmarks use synthetic fixtures. They do not prove productivity gains or prompt-injection immunity.
- Remaining reliability and UX work is tracked in issues #50–#56; installation validation remains exploratory.

Please report reproducible problems at https://github.com/kulharshit21/contextforge-ai/issues. Contributions and independent testing are welcome.
